# 老人看护对话机器人（Pipecat + ElevenLabs）

本地单机、文本可演示的老人看护对话机器人业务闭环。核心三大模块：
**紧急检测 / 用药提醒 / 记忆**。语音层（Pipecat + ElevenLabs）已留骨架，
业务逻辑与交互层解耦，后续上语音时无需改动业务代码。

## 设计要点

- **业务与交互解耦**：`Brain.process_turn()` 是 CLI 与语音层共用的唯一入口。
  CLI 用打字，语音层用 STT/TTS，行为完全一致。
- **安全优先**：紧急检测、用药确认为**规则驱动**，不依赖 LLM，保证低延迟与确定性。
  LLM 只用于日常闲聊与记忆工作（情景切分/抽取/巩固）；记忆组件全部不在安全判定路径上，
  失败即降级，绝不阻塞对话。
- **精确查询范式**：精确数据查询（用药计划/健康记录/紧急事件）统一走意图识别→确定性查询函数，
  精确数据只来自 DB，不由 LLM 生成（不使用 function-calling）。
- **事件记忆是地基**：用药记录、健康读数、紧急事件都写入结构化表，供三个模块共享；
  记忆则在其上按"情景切分 → 语义巩固 → 检索式回忆"三阶段流动（见下文）。
- **离线可跑**：未配置 LLM key 时用模板回复（FakeLLM），业务闭环与测试不受影响。

## 快速开始

```bash
# 1. 创建并激活环境
conda create -y -n eldercare python=3.11
conda activate eldercare

# 2. 安装依赖
pip install -r requirements.txt

# 3. 配置（可选：不配 key 也能跑，用离线模板回复）
cp .env.example .env
# 编辑 .env 填入 OPENAI_API_KEY 以启用真实对话

# 4. 写入种子数据
python -m seed.seed_data

# 5. 启动文本演示
python -m app.cli
```

## 演示指令（CLI 内）

| 指令 | 作用 |
|------|------|
| `/who` | 查看当前老人档案 |
| `/time 08:00` | 模拟到点，触发该时间的用药提醒 |
| `/silence` | 模拟老人沉默（紧急确认中会升级为紧急并通知家属）|
| `/tick [HH:MM]` | 手动驱动一次记忆脉冲（巩固 / 前瞻过期 / 清理等条件触发）；无参数用当前时间，带 `HH:MM` 则注入"今天该时刻"便于离线演示 |
| `/events` | 查看已记录的健康 / 紧急 / 家属通知 |
| `/mem` | 查看当前记忆状态（情景 Episode / 主题场景 MemScene / 有效前瞻 Foresight / 画像 / 召回预览 + 工作记忆窗口）|
| `/quit` | 把残留窗口折叠入记忆并退出 |

## 记忆模型（常驻在线，三阶段）

设备是长期常驻的，没有"开始/结束会话"的概念。长期记忆不再是"一条反复覆写的
running summary"，而是借鉴人类记忆生命周期的**三阶段模型**：

1. **情景切分（Episode）**：连续对话按**语义边界**切分（久别/轮数上限兜底），每段一次
   LLM 调用抽成情景摘要 + 原子事实 + 带时限前瞻 + 人物。Episode **永久保留、可检索**，
   取代过去"折叠后即销毁"。
2. **语义巩固（MemScene / 画像 / 趋势）**：空闲或未巩固情景累积到条件时，把相关 Episode
   归并成主题场景 `MemScene`，**整体重写**一份有界稳定的老人画像 `ElderProfile`，并归纳
   健康/情绪趋势（数值只取自结构化读数，不由 LLM 编造）。取代单条会漂移的摘要。
3. **检索式回忆（Recall）**：闲聊时按当前话题从多源记忆（情景/事实/前瞻/场景/人物）
   "必要且充分"地召回 top-k 注入，有界且不编造，不再全量灌入。

围绕三阶段的支撑机制：

- **工作记忆滚动窗口**：最近若干轮原文常驻上下文；超过 token 预算
  （`MEM_TOKEN_BUDGET`，默认 1500）即增量折叠。**running summary 降级为"即时 gist"兜底**，
  与检索式注入并存，不再是唯一长期记忆。
- **带时限前瞻（Foresight）**：识别到"下周三复查""明天孙子来看我"等未来关注点时落库并带
  到期日；到期后自动失活、不再注入日常上下文，但保留审计（单调失活，不改事件时间）。
- **人物记忆（Person）**：从对话归集提到的人物与关系，再次提及只更新最近片段而非新建。
- **近期原文落盘与重启恢复**：每轮 user/assistant 原文 append 落盘；重启时恢复最近窗口，
  已巩固的旧原文可按保留天数清理（Episode 摘要长期保留）。
- **时间感**：每轮把"当前时刻 / 时段 / 距上一句多久"注入上下文，让机器人有昼夜与间隔感。

### 统一条件触发（TriggerEngine）

巩固、前瞻过期、原文清理、主动关心等记忆类周期工作统一抽象为 `Trigger`（谓词 + 动作 +
去重 + 冷却），由两个时钟源驱动：每轮对话结束后的 `on_turn`，以及低频被动脉冲 `on_pulse`
（宿主主循环 / CLI `/tick` / 测试注入 `now`）。去重与冷却只依赖落库的 `TriggerFire`，
**跨重启幂等**；单个触发器异常被隔离，绝不影响其他触发器与主对话返回。

> **用药提醒仍保留独立的时间调度（APScheduler），不并入 TriggerEngine**——用药是安全关键、
> 要求准时的定时任务，与"空闲/累积"驱动的记忆工作性质不同，二者刻意解耦。

用 `/mem` 可直观看到情景、主题场景、有效前瞻、画像与"按当前话题召回了哪些记忆"；
用 `/tick` 可手动驱动一次记忆脉冲，观察巩固与前瞻过期发生。

## 推荐演示脚本

```
/time 08:00              # 主动提醒吃药（含药名/形状/剂量/饭前后）
药吃过了                  # 确认服药，闭环
我今天吃药了吗            # 防重复服用：回答"已经吃过"
我几点吃药               # 精确查询用药时间表（意图识别→确定性查询 DB，不由 LLM 生成）
我血压量了是150/95        # 健康数据自动记录
今天去公园遇到王阿姨了    # 闲聊（多聊几轮跨话题后，较早的一段会被切成 Episode）
/tick                    # 手动驱动一次记忆脉冲：把情景巩固进主题场景 + 重写画像
/mem                     # 查看情景 / 主题场景 / 有效前瞻 / 画像 / 召回预览
你还记得我今天遇到谁吗    # 验证：按话题从情景/人物记忆里召回，而非全量灌入
我这胸口有点闷            # 触发告警 + 主动确认 + 通知家属
没事没事我就是喘口气      # 确认无事 -> 降级取消
救命啊我不行了            # 最高级 -> 通知全部联系人 + 建议120
/events                  # 查看全程留痕
/quit                    # 折叠残留窗口并退出
```

> 演示折叠效果时可临时调小预算：`MEM_TOKEN_BUDGET=40 MEM_FOLD_BATCH=2 python -m app.cli`。
> 想更快看到情景切分，可调小轮数上限：`MEM_EPISODE_MAX_TURNS=4 python -m app.cli`。
> 数据结构有变更时直接删库重建：`rm -f elder_care.db && python -m seed.seed_data`
> （`create_all` 会自动建好 Phase 3 的情景/场景/前瞻/画像/趋势/人物/触发等新表）。

## 运行测试

```bash
python -m pytest
```

当前共 **231** 个测试，全绿。覆盖范围：

- **安全闭环**：紧急分级与误报抑制、确认升级/降级、沉默升级、用药确认闭环与防重复、
  健康数据抽取。
- **记忆链路（Phase 3）**：语义边界切分与降级、MemCell 抽取与离线降级、情景巩固幂等与
  同主题唯一 active 场景、检索式回忆有界与"不编造"、前瞻到期失活、人物再提及归并、
  近期原文落盘/恢复/清理、TriggerEngine 去重/冷却/跨重启幂等/失败隔离。
- **属性测试（hypothesis）**：随机对话 + 脉冲序列驱动，断言窗口有界、切分不丢段、
  前瞻单调失活、召回有界、触发器幂等等不变量。
- **端到端生活场景**：独居的一天 / 深夜求救 / 反复漏药通知家属 / 认知障碍防误服，
  以及跨话题记忆的切分→巩固→召回。

> 测试均使用内存库，不依赖 `elder_care.db`。
